# Industrial Lab

Два интерактивных портфолио-кейса на Vanilla JavaScript, Three.js r180 и GSAP 3.13.0.

## Запуск

Нужен Node.js. Установка пакетов и сборка не требуются:

```sh
npm start
```

Открыть http://127.0.0.1:4173. Через file:// ES-модули не работают.

* `/#plant` — промышленный мониторинг: общий план, три детальных вида, возврат, подсветка выбора, шейдерные потоки и пламя.
* `/#pump` — центробежный насос: разборка на пять групп, ползунок разборки, выбор компонентов, сечение корпуса, смена материала и вращение ротора.

## Устройство

* `dist/js/engine.js` — WebGLRenderer, OrbitControls, PMREM-окружение, PBR-карты, picking, проецируемые HTML-метки, GSAP-переходы камеры, очистка ресурсов.
* `dist/js/plant.js` — процедурная установка и внутренние виды. GLSL-анимация потоков и трёх пересекающихся плоскостей пламени.
* `dist/js/pump.js` — процедурная сборка насоса. Разборка перемещает группы по общей оси; сечение использует clipping planes.
* `dist/js/app.js` — маршрутизация по hash, общий UI и необязательная интеграция WebMCP.
* `dist/style.css` — две темы, адаптивная компоновка и доступные состояния элементов.

PBR — реальные MeshStandardMaterial с процедурными картами base color, roughness и tangent-space normal. Карты генерируются детерминированно, повторно используются между сценами. Это не фотосканированные текстуры. Окружение генерируется через RoomEnvironment и PMREM. Внешние 3D-модели не используются.

Все библиотеки лежат в `dist/vendor`. Шрифты Manrope и IBM Plex Mono загружаются из Google Fonts, при недоступности используются системные. Лицензия Three.js находится рядом с библиотекой; ссылка на лицензию GSAP — в `GSAP-LICENSE.txt`.

## Производительность и доступность

Ограничение pixel ratio, кэширование статических теней, пауза рендера в скрытой вкладке, очистка геометрий и материалов при смене кейса. Кнопка HD/SD отключает тени и снижает разрешение. На мобильном панель перемещается под сцену. Все действия доступны кнопками, а не только кликами по модели. Учитывается prefers-reduced-motion; декоративная анимация по умолчанию приостановлена для таких пользователей.

Нужен WebGL 2. Фактическая частота кадров зависит от GPU и браузера. Показатели процесса синтетические. Модели концептуальные: не CAD, не гидродинамическая симуляция, не проект реальной установки.

## Проверка

`npm run check` проверяет синтаксис. `qa.cjs` — использованный сценарий проверки Playwright; путь к Playwright адаптирован под локальную среду Codex. Он проверяет переходы ко всем трём деталям установки, возврат, переключатели, разборку, выбор детали и покрытия, диалог, мобильную ширину и повторную смену сцен; делает локальные скриншоты. Для использования вне этой машины замените абсолютный require на `require('playwright')` и установите Playwright.

WebMCP — необязательное прогрессивное улучшение, без влияния на обычный браузер. Нативная валидация требует браузера с поддержкой `document.modelContext`; в обычном Playwright она недоступна.

## Публикация

`dist/` — готовый статический сайт. Его можно размещать целиком на Netlify, Vercel или GitHub Pages. Build command не нужен; publish/output directory — `dist`. Отдельные ссылки используют `#plant` и `#pump`, серверные rewrite-правила не требуются. Конфигурация публикации через Sites хранится в `.openai/hosting.json`.

## Как показать заказчику

1. Мониторинг: покрутить общий план → выбрать S-101 → показать внутренние перегородки и поток → вернуться → открыть факел.
2. Насос: разобрать → выбрать рабочее колесо → изменить степень разборки → собрать → включить сечение → сменить покрытие.

Честное описание: «Два концептуальных 3D-прототипа: промышленный мониторинг с drill-down и интерактивная разборка насоса. Three.js, процедурные PBR-карты, GLSL-эффекты, GSAP». Не выдавать за коммерческие внедрения или опыт интеграции с реальным оборудованием.
